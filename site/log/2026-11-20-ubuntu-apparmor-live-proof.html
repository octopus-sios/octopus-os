Ubuntu 26.04 AppArmor 5.0.2 & systemd confinement fixes, verified with a live stock-enforced agent run.

1. AppArmor ABI 4.0 unprivileged stacking (<profile>//&unconfined (enforce))

On Ubuntu 26.04 LTS (AppArmor 5.0.2, ABI 4.0), unprivileged change_profile / aa-exec transitions stack onto unconfined, causing /proc/<pid>/attr/current to report labels of the form <profile>//&unconfined (enforce). Previously, octopus-linux-process-authority rejected those stacked labels when verifying caller confinement in Host::prepare, and generated AppArmor signal/ptrace rules did not match stacked peers.

registry/worker_environment_kind/process_session/packages/octopus-linux-process-authority/src/service.rs now parses caller labels via enforced_profile_name(), stripping " (enforce)" and an optional trailing "//&unconfined" while continuing to reject non-enforced or multi-profile stacked labels (covered by two new unit tests). crates/octopus-verifiers/src/process_authority/linux.rs adds matching signal (send) peer={name}//&unconfined, and ptrace (read, trace) peer={name}//&unconfined, rules.

2. Cross-mount-namespace Unix socket delegation under systemd hardening

Running the live runtime under octopus-runtime.service with ProtectSystem=full, ProtectKernelTunables=yes, and ProtectControlGroups=yes places the runtime and its confined children in a private mount namespace, while octopus-process-authority.service binds /run/octopus-process-authority/control.sock in the host mount namespace. Standalone aa-exec tests passed, but confined delegation inside systemd failed with Permission denied (os error 13): 

apparmor="DENIED" operation="connect" class="file" info="Failed name lookup - disconnected path" error=-13 profile="octopus-..." name="run/octopus-process-authority/control.sock"

crates/octopus-verifiers/src/process_authority/linux.rs now emits flags=(attach_disconnected, mediate_deleted) on generated AppArmor profile headers (validated with apparmor_parser --warn=all --Werror across every generated profile shape). Re-testing inside systemd-run with identical unit hardening confirmed that delegation succeeds when explicitly permitted (allow_sandbox_delegation: true → rc=0) and remains blocked when disallowed (allow_sandbox_delegation: false → rc=1, PermissionError: [Errno 13] Permission denied).

3. Pathname Unix control sockets (app_server_control_root) under AppArmor

Life processes that bind or connect pathname Unix control sockets under app-server-control/*.sock require AppArmor write access to app_server_control_root. Commit 59a6c0f adds "app_server_control_root" to "write_root_slots" across all 36 life.json descriptors declaring it in coordinate_root_slots (35 provider descriptors plus system_context_memory_projection/life.json) and updates maintenance_observer.rs accordingly.

Live stock-enforced multi-step proof

With 59a6c0f deployed on a hardened Ubuntu 26.04 LTS e2-micro VM (Linux 7.0.0-1017-gcp x86_64) under octopus-runtime.service and octopus-process-authority.service, a live multi-step agent turn ran end-to-end with stock sandbox_mode: "enforced" across every life.json and tool.json descriptor and zero per-clone workarounds.

Verified confined tool chain

  • Delegated authoring write: file.write__authoring delegated cleanly across systemd's private mount namespace via /run/octopus-process-authority/control.sock.
  • Confined workspace write: workspace.write_file wrote the 31-byte proof artifact inside the task workspace.
  • Non-delegating leaf execution: workspace.exec ran inside its leaf AppArmor sandbox with PR_SET_NO_NEW_PRIVS=1 (NoNewPrivs: 1) and received cat: /proc/self/attr/current: Permission denied on stderr—direct proof of active kernel confinement.
  • Clean kernel profile lifecycle: journalctl -k recorded 9 distinct per-launch profiles transitioning through operation="profile_load", enforced execution (//&unconfined), and operation="profile_remove" with zero blocking denials.
  • Steady-state health: After cleaning up the proof workspace, octopus doctor reported 22 interfaces · 18 life processes, client 26/26, probes 2/2 passed, and executables 22/22 (result PASS) with both hardened systemd services active.
