1. Fixing the Linux /proc/self/exe restart trap

Previously, crates/octopus-app/src/main.rs resolved std::env::current_exe() inside start_again() after shutting down the daemon. On Linux, renaming the active bundle directory to .prev before restarting causes /proc/self/exe to follow the moved inode, re-executing the old binary instead of the upgraded installation.

run_up() now resolves and snapshots the restart executable path at startup via resolve_restart_executable(), honoring an absolute OCTOPUS_RUNTIME_BIN environment variable (failing closed on relative paths) and falling back to the startup executable path. Three unit tests cover override, relative-path rejection, and default fallback behavior.

2. Out-of-place CLI staging & atomic Linux self-updates

app/scripts/package-cli.cjs and app/scripts/build-cli.cjs gained --output=<dir> / OCTOPUS_CLI_RUNTIME_DIR staging so new builds never mutate a running runtime directory in place, and runtime-build-receipt.json now records git revision, modified-source state, and build timestamp alongside binary SHA-256 digests.

app/scripts/safe-self-update.cjs now supports --target=mac|cli|auto (defaulting to cli on Linux and mac on macOS), verifies receipt SHA-256 hashes and octopus doctor, checks the movement ledger for active turns without requiring desktop client directories, performs atomic directory or POSIX symlink swaps, and falls back to systemctl restart/rollback when configured via --systemd-unit.

3. Hardened systemd service & Linux CLI release packaging

packaging/linux/octopus-runtime.service runs octopus up as an unprivileged octopus user in the octopus-process group with Restart=on-failure, UMask=0077, NoNewPrivileges=yes, ProtectSystem=full, ProtectKernelTunables=yes, ProtectKernelModules=yes, ProtectControlGroups=yes, LockPersonality=yes, and RestrictSUIDSGID=yes.

app/scripts/release-linux.cjs validates the staged Linux CLI receipt, binary digests, required registry files, and managed Codex payload, bundles the systemd unit template, builds Octopus-<version>-linux-<arch>.tar.gz, extracts the tarball into a temporary directory for byte-for-byte verification against the staged tree, and writes the matching .sha256 file.
