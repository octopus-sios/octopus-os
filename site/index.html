An operating-system kernel for persistent, least-privilege agents.

octopus-os keeps goals, permissions, runs, tools, and external events as explicit durable records outside the model loop. A small Rust kernel forms grants on every arrival, admits artifact movements, and records every crossing and refusal in an append-only ledger.

Architecture highlights

Models and tools communicate only through declared interfaces; neither is the runtime authority. The system runs on macOS 14+ (desktop client and terminal CLI) and on headless Linux (x86_64 CLI runtime, systemd supervision, and AppArmor confinement).

Formed grants outside the model

Effective authority is recomputed at every arrival by intersecting the worker pin's ceiling, its Execution Environment (EE) chain, and authored run bindings. Nested EEs can only narrow authority, and tool doors enforce the formed grant outside the model.

Append-only movement ledger

Every artifact hand-in, tool dispatch, verification mark, and typed refusal is appended to the movement ledger. Projections and indexes are rebuildable views, never the source of truth. Runs are durable records that park and wake on arriving artifacts.

Linux AppArmor 4.0, cgroup v2 & systemd

octopus-process-authority compiles per-launch AppArmor 4.0 profiles and binds processes to delegated cgroup v2 subtrees before exec, keeping confinement intact across forks and atomic file replacements. A hardened octopus-runtime.service unit and safe-self-update.cjs handle unattended Linux operation and rollback.

Registry-owned interfaces & self-evolution

Providers, channels, sensors, rooms, workers, and verifiers attach as registry folders without editing the kernel. Under policy, a run can reshape its own execution environment for future work—keeping self-improvement an explicit, falsifiable research question rather than a marketing claim.

Standalone MIT tools & empirical benchmarks

Two companion packages in examples/ run independently without installing Octopus or connecting a model provider. Each reports measured data alongside its exact scope boundaries.

mcp-identity-guard

A Unix Rust library and CLI implementing a provider-qualified MCP stdio gateway with SHA-256/metadata executable pins, scoped secret handles, multi-encoding scrubbing, minimum-cost conjunctive recourse, and a hash-chained audit ledger.

Scope boundary: local synthetic fixtures with one benign accuracy trial. Not a general sandbox or production security certification.

agent-ready-radar

A zero-dependency Python 3.12+ CLI and library for bounded HTTP observations of /llms.txt, /llms-full.txt, /agents.md, MCP discovery endpoints, plugin manifests, and robots AI directives.

Scope boundary: dated purposive sample (33/60 verified /llms.txt, 9/60 /agents.md), not a web-wide readiness estimate.
